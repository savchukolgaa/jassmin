# AGENTS.md: aspire-apphost

Aspire TypeScript AppHost, used for **local development only**. Production runs `pnpm build && pnpm start`.

- `apphost.mts` declares the resources:
  - `postgres`: PostgreSQL container with a persistent data volume.
  - `jassmindb`: the app database on that server.
  - `db-migrate`: child of `jassmindb` that runs `pnpm db:migrate` on every run. `web` waits for it to complete (`waitForCompletion`). It owns the root `pnpm install` (`withPnpm()`), so every other JavaScript resource uses `withPnpm({ install: false })`.
  - `db-seed` / `db-rollback`: explicit-start children of `jassmindb` that run `pnpm db:seed` / `pnpm db:rollback` against the Aspire database, whose password only Aspire knows.
  - `db-mark-abandoned-carts`: explicit-start child of `jassmindb` that runs `pnpm db:mark-abandoned-carts` (#19) once, after `db-migrate`. In production the job runs hourly from cron instead.
  - `db-send-order-emails`: explicit-start child of `jassmindb` that runs `pnpm db:send-order-emails` (#45) once, after `db-migrate`, with `SMTP_URL` from `smtp4dev`. It sends queued order emails that are due, e.g. after smtp4dev was down at checkout. In production the job runs every 5 minutes from cron.
  - `db-sync-cms`: explicit-start child of `jassmindb` that runs `pnpm db:sync-cms` (#40) once, after `db-migrate` and once `cms` is up, with `STRAPI_URL` from `cms` (`STRAPI_SYNC_TOKEN` comes from the root `.env`). It pushes queued order and stock changes to Strapi, e.g. after Strapi was down at checkout. In production the job runs every 5 minutes from cron.
  - `cms-sync-secret`: a generated, persisted secret parameter (`addParameterWithGeneratedValue`), passed to both `cms` and `web` as `CMS_SYNC_SECRET` (#40). Strapi sends it to the app's `/cms/*` sync routes.
  - `strapidb`: the Strapi CMS database on the same server.
  - `cms`: Strapi (`addJavaScriptApp("cms", "../cms", { runScriptName: "develop" })`) on port 1337. It gets `DATABASE_URL` from `strapidb.uriExpression()`, waits for `strapidb` and is health-checked on `/_health`. `withPnpm({ install: false })` is used because the root install run for `db-migrate` already installs the `cms` workspace package. Strapi's secrets come from `cms/.env`. It also gets `CMS_SYNC_SECRET` and, set after `web` is declared, `JASSMIN_APP_URL` from `web`'s `http` endpoint, because product and order edits in the Strapi admin write through to the app (#40). `cms` doesn't wait for `web` (that would be a cycle), so such an edit fails with a clear message while the app is down.
  - `cms-seed`: explicit-start child of `cms` that runs `pnpm seed --token` against `strapidb` (whose password only Aspire knows) and prints the app's API token in its logs.
  - `smtp4dev`: fake SMTP server container (`rnwood/smtp4dev:v3`) for local email. Its `smtp` endpoint (container port 25) is passed to `web` as `SMTP_URL`; its `http` endpoint is the web UI that shows every caught message (open it from the dashboard).
  - `web`: the React Router dev server (`addViteApp("web", "..")`, run with pnpm, `install: false`). It has a reference to `jassmindb` (injected as `JASSMINDB_URI`), waits until the database is healthy and until `db-migrate` has completed. It also references `cms` and gets its endpoint as `STRAPI_URL`, but deliberately doesn't wait for it: CMS outages show up as 503s on CMS pages instead of blocking the shop. It gets `SMTP_URL` from `smtp4dev` and doesn't wait for it either, and `CMS_SYNC_SECRET` from `cms-sync-secret`.
- `.aspire/modules/` is the **generated** SDK. Don't edit or commit it; it's regenerated by `aspire restore` / `aspire add`. Read its typings to find the exact API (e.g. `addPostgres`, `withDataVolume`, `addViteApp`, `withPnpm`).
- Add integrations with `aspire add <name>` (e.g. `aspire add redis`). The package versions are recorded in the root `aspire.config.json`.
- This is a **standalone pnpm package with its own lockfile**, not a member of the root workspace. Aspire installs it with `pnpm install --ignore-workspace`, which ignores every `pnpm-workspace.yaml`.
- For the same reason, always start Aspire with **`pnpm aspire <cmd>`** from the repo root. `scripts/aspire.mjs` sets `pnpm_config_allow_builds` so pnpm 12 accepts esbuild's build script, which comes in through `tsx`. That variable also overrides `allowBuilds` for the root install Aspire runs for `db-migrate`, so it lists the Strapi entries (`@swc/core`, `core-js-pure`) as well. Keep it in sync with `pnpm-workspace.yaml`.
- `tsconfig.apphost.json` needs `"types": ["node"]`, because TypeScript 7 no longer auto-includes `@types`.
- Check your changes with `pnpm aspire:build` from the repo root (`tsc -p tsconfig.apphost.json`). Biome lints `apphost.mts` together with the rest of the repo.
- If Aspire fails with DCP/TLS errors ("The SSL connection could not be established", "container volumes did not become ready"), run `aspire doctor`. HTTPS-scanning antivirus software (e.g. Avast Web Shield) can block DCP's local TLS.
