# Plan: Create analytics schema: sessions and user_events (#5)

Branch: `issue/5`
Worktree: `.claude/worktrees/issue-5`
Status: Planned

## Goal
As a data analyst, I want visitor sessions and a granular behavioural event stream stored in
PostgreSQL so that I can build conversion, LTV and churn models. This issue adds the Drizzle
schema and one migration (with its hand-written rollback) for the `sessions` and `user_events`
tables, the FK `carts.session_id → sessions.session_id`, and the shared `EVENT_TYPES` union in
`app/lib/`. Recording sessions and events is #18, not this issue.

## Decisions & assumptions
- **Shared union**: `EVENT_TYPES` (`as const`) and `EventType` go in `app/lib/enums.ts`, next to
  `PAYMENT_METHODS`, which is the existing pattern for a text column + CHECK. The row types
  `AnalyticsSession` and `UserEvent` go in a new `app/lib/analytics.ts`, mirroring
  `app/lib/commerce.ts`, and `schema.test.ts` asserts they match `$inferSelect`.
- **`event_type` is `text` + CHECK** (`user_events_event_type_check`), built from `EVENT_TYPES`
  like `orders_payment_method_check`, with `.$type<EventType>()`. Not a `pgEnum`: the issue asks
  for text, and adding an event type later is a one-line CHECK rewrite rather than an
  `ALTER TYPE … ADD VALUE` (which can't be rolled back cleanly).
- **Primary keys**: `sessions.session_id` and `user_events.event_id` are `uuid` with
  `default uuidv7()`, like `products.public_id`. UUID v7 is time-ordered, so inserts into the
  append-only event stream stay index-friendly, and #18 can still pass its own id.
- **Timestamps**: `sessions.started_at timestamptz not null default now()`, `ended_at` nullable.
  `user_events.created_at timestamptz not null default now()` (the issue says
  `default now()`; `not null` follows every other `created_at` in the schema).
- **Nullable text columns**: `landing_page`, `traffic_source`, `device_type` (sessions);
  `source`, `medium`, `campaign`, `device_type`, `referrer` (user_events). `anonymous_id` is
  `text not null` in both.
- **`event_properties`**: `jsonb`, nullable, typed `.$type<EventProperties>()` where
  `EventProperties = Record<string, unknown>` lives in `app/lib/analytics.ts`.
- **FK delete actions**:
  - `sessions.user_id → users.id` and `user_events.user_id → users.id`: `on delete set null`
    (confirmed). Rows keep `anonymous_id`, so behaviour stays usable as anonymous data.
  - `user_events.session_id → sessions.session_id`: `not null`, `on delete cascade` (an event
    can't outlive its session).
  - `user_events.product_id → products.id`: `on delete set null`, like `order_items.product_id`,
    so historical events survive a product deletion.
  - `carts.session_id → sessions.session_id`: `on delete set null` (the cart, its items and its
    status matter more than the visit link). Constraint name generated by drizzle-kit
    (`carts_session_id_sessions_session_id_fk`).
- **Indexes** (explicit snake_case names, as the AGENTS rules require):
  - From the issue: `user_events_user_id_created_at_idx (user_id, created_at)`,
    `user_events_anonymous_id_idx (anonymous_id)`,
    `user_events_event_type_created_at_idx (event_type, created_at)`,
    `sessions_anonymous_id_idx (anonymous_id)`.
  - Added: `sessions_user_id_idx (user_id)` and `user_events_session_id_idx (session_id)`. #18's
    `linkVisitorToUser` and per-user session queries need the first, the cascade from
    `sessions` and per-session funnels need the second. `carts_session_id_idx` already exists.
- **Migration name**: `pnpm db:generate --name analytics_schema` → `0002_analytics_schema.sql`
  (the number may change after a rebase, step 7). Rollback in
  `rollbacks/0002_analytics_schema.sql`: drop the carts FK, then `user_events`, then `sessions`.
- **No backfill before adding the carts FK**: nothing writes `carts.session_id` yet (only the
  schema and `Cart` type mention it), so existing rows are all `NULL` and the FK applies cleanly.
- **Deviation (step 4): the migration was not applied to the shared dev database.** #26 and
  #14 generate their own `0002_*` migrations from the same base, and Drizzle's `migrate()`
  skips any migration whose timestamp is older than the latest applied one, so applying this
  branch's `0002` there could silently skip theirs. Migrate → rollback → migrate is verified
  on a throwaway database by `migrator.test.ts` instead. Apply it to the dev DB after merging.
- Table names stay `sessions` / `user_events` as in the issue. The TS export is `sessions`, and
  the row type is `AnalyticsSession` to avoid confusion with the cookie session in
  `app/.server/session.ts` (#9).

## Resolved questions
- **What happens to analytics rows when a user is deleted?** — `on delete set null` for
  `sessions.user_id` and `user_events.user_id`: `restrict` would block deleting anyone who ever
  visited, and `cascade` would erase the behaviour history (source: confirmed by the user).
- **Keep the two extra indexes (`sessions_user_id_idx`, `user_events_session_id_idx`)?** — Yes,
  add both (source: confirmed by the user).
- **Does the `carts.session_id` FK belong here?** — Yes, #4 left it out on purpose
  (source: `app/.server/db/schema.ts:88`, `app/.server/AGENTS.md` "gets its FK to `sessions` in
  #5", #5 Technical).
- **Where does the event type union live?** — `app/lib/` (#5 acceptance criteria); text + CHECK
  from a shared `as const` array follows `PAYMENT_METHODS` / `orders_payment_method_check`
  (source: `app/lib/enums.ts`, `app/.server/db/schema.ts`).
- **Who writes sessions/events and links them to users?** — #18 (`getVisitor`, `trackEvent`,
  `linkVisitorToUser`), called from `onUserAuthenticated` (source: #18,
  `app/.server/services/auth.ts:101`). No query functions are needed here.
- **How are migrations reversed?** — Hand-written `db/rollbacks/<tag>.sql`, run by
  `rollbackLatest` (source: `app/.server/AGENTS.md`, `README.md` "Database migrations").
- **Are existing `carts.session_id` values safe for the new FK?** — Yes, no code sets it yet
  (grep for `sessionId` finds only the schema, `~/lib/commerce` and `schema.test.ts`).
