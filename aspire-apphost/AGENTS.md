# AGENTS.md: aspire-apphost

Aspire TypeScript AppHost, used for **local development only**. Production runs `pnpm build && pnpm start`.

- `apphost.mts` declares the resources:
  - `postgres`: PostgreSQL container with a persistent data volume.
  - `jassmindb`: the app database on that server.
  - `web`: the React Router dev server (`addViteApp("web", "..")`, run with pnpm). It has a reference to `jassmindb` (injected as `JASSMINDB_URI`) and waits until the database is healthy.
- `.aspire/modules/` is the **generated** SDK. Don't edit or commit it; it's regenerated by `aspire restore` / `aspire add`. Read its typings to find the exact API (e.g. `addPostgres`, `withDataVolume`, `addViteApp`, `withPnpm`).
- Add integrations with `aspire add <name>` (e.g. `aspire add redis`). The package versions are recorded in the root `aspire.config.json`.
- This is a **standalone pnpm package with its own lockfile**, not a member of the root workspace. Aspire installs it with `pnpm install --ignore-workspace`, which ignores every `pnpm-workspace.yaml`.
- For the same reason, always start Aspire with **`pnpm aspire <cmd>`** from the repo root. `scripts/aspire.mjs` sets `pnpm_config_allow_builds={"esbuild":true}` so pnpm 12 accepts esbuild's build script, which comes in through `tsx`.
- `tsconfig.apphost.json` needs `"types": ["node"]`, because TypeScript 7 no longer auto-includes `@types`.
- Check your changes with `pnpm aspire:build` from the repo root (`tsc -p tsconfig.apphost.json`). Biome lints `apphost.mts` together with the rest of the repo.
- If Aspire fails with DCP/TLS errors ("The SSL connection could not be established", "container volumes did not become ready"), run `aspire doctor`. HTTPS-scanning antivirus software (e.g. Avast Web Shield) can block DCP's local TLS.
