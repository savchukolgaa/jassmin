## Goal
As a developer, I want the core PostgreSQL schema (shared enums, `users`, `products`) created through migrations, so that catalog and authentication features have a reliable data foundation. This issue sets up Drizzle Kit migrations with `db:migrate` / `db:rollback` / `db:seed` scripts, creates the four enums and the two tables, seeds sample perfumes, and exports the enum values as TypeScript unions from `app/lib/`.

## Decisions & assumptions
- **Migrations:** generated by `drizzle-kit generate` into `app/.server/db/migrations/` (already configured). Applied with `drizzle-kit migrate` (`pnpm db:migrate`), which records them in `drizzle.__drizzle_migrations`.
- **Rollback:** Drizzle Kit has no down migrations. For each generated migration `<tag>.sql`, we commit a hand-written `app/.server/db/rollbacks/<tag>.sql` with the reverse DDL. `rollbackLatest(db)` (in `app/.server/db/migrator.ts`) finds the latest applied migration in `drizzle.__drizzle_migrations` (by `created_at`, which equals the journal entry's `when` in `migrations/meta/_journal.json`), runs its down SQL and deletes that row **in one transaction**. It throws a clear error if the down file is missing. Down files are kept outside `migrations/` so drizzle-kit never sees them. Rolling back the first migration leaves the empty `drizzle` schema in place, which is harmless.
- **Enums are defined once, in `app/lib/enums.ts`** as `as const` arrays (`GENDERS`, `ORDER_STATUSES`, `PAYMENT_STATUSES`, `CART_STATUSES`) plus derived unions (`Gender`, `OrderStatus`, `PaymentStatus`, `CartStatus`). `schema.ts` builds the `pgEnum`s from those arrays (`pgEnum("gender_type", GENDERS)`). `app/lib` is isomorphic, so the server may import it. The TS types and DB enums can't drift, and a unit test checks this.
- **Schema style:** camelCase TS names mapped to snake_case by `casing: "snake_case"` (`app/.server/AGENTS.md`). Explicit names for constraints and indexes: `products_stock_quantity_check`, `products_gender_idx`. `users.email` uses `.unique()` (generates `users_email_unique`).
- **Money:** `price` is `numeric(10, 2)` in Drizzle's default string mode, so values are exact. Callers format or convert it. No floats for money.
- **Timestamps:** `timestamp(…, { withTimezone: true })` → `timestamptz`, `defaultNow()`.
- **NOT NULL on defaulted columns (confirmed, Q1):** `stock_quantity`, `acquisition_channel` and both `created_at` columns are NOT NULL in addition to their defaults. This deliberately goes beyond the issue's column list.
- **Pack size column (confirmed, Q2):** `products.pack_size integer not null default 1` with `check (pack_size > 0)` (`products_pack_size_check`). `volume_ml` is the volume of **one** unit, so the 3× tester set is `packSize: 3, volumeMl: 10`. The total volume is `pack_size * volume_ml`, and the UI calculates it.
- **Public GUID v7 key (confirmed, Q3):** `products.public_id uuid not null unique default uuidv7()` (`products_public_id_unique`). `id` stays the serial PK, so #4/#5 foreign keys don't change. `public_id` is a stable natural key for the seed (and later for public URLs/imports). `uuidv7()` is built into PostgreSQL 18, which both Aspire and the README's Docker example use (`postgres:18`); README states PostgreSQL 18+ as a requirement.
- **Script DB connection:** the CLI scripts create their own short-lived pool from the database URL and close it at the end. This avoids `getEnv()`, which also requires `SESSION_SECRET`. To share code, `index.ts` exports a `createDb(connectionString)` factory, and the app keeps using the single `db` singleton. A small `getDatabaseUrl(source)` helper in `env.ts` applies the same `JASSMINDB_URI || DATABASE_URL` precedence, and `parseEnv` uses it too.
- **Aspire (confirmed, Q4):** Aspire generates the `jassmindb` password, so terminal runs of `pnpm db:*` can't reach the Aspire database (same constraint as `cms-seed`). We add a `db-migrate` resource (`pnpm db:migrate`) that runs on every `pnpm aspire run`, and `web` uses `.waitForCompletion(dbMigrate)` so the app always starts on an up-to-date schema. We also add `db-seed` and `db-rollback` explicit-start resources, all children of `jassmindb`.
- **Seed:** `pnpm db:seed` inserts about 9 sample perfumes covering women, men and unisex, including a 3× tester set (`packSize: 3`). Names and descriptions are in Ukrainian, `image_url` is `null` and `fragrance_family` is filled in (it's an ML feature). Each sample product has a fixed, hard-coded UUID v7 `publicId`. The seed inserts with `onConflictDoNothing({ target: products.publicId })` in one transaction, so re-running it adds only missing samples and never duplicates or overwrites rows. This matches the "safe to run repeatedly" behaviour of `cms/scripts/seed.ts`. No users are seeded, because password hashing arrives with auth (#9).

## Resolved questions
- **Q1: Should defaulted columns also be NOT NULL?** Yes, all of them: `products.stock_quantity`, `users.acquisition_channel`, `users.created_at`, `products.created_at` (source: user answer).
- **Q2: How should the 3× tester set be stored?** In a dedicated column: `products.pack_size` (source: user answer).
- **Q3: How should the seed avoid duplicates?** With a unique GUID v7 key, `products.public_id` (source: user answer).
- **Q4: Should migrations run automatically under Aspire?** Yes: `db-migrate` runs before `web` (source: user answer).
- **Which migration tool?** Drizzle Kit, with output in `app/.server/db/migrations` and snake_case casing (source: `drizzle.config.ts`, `package.json`, `app/.server/AGENTS.md` → "Database").
- **Where do the schema and migrations live?** In `app/.server/db/schema.ts` and `app/.server/db/migrations/`. Never edit an applied migration (source: `app/.server/AGENTS.md`).
- **Which DB URL do the scripts use?** `JASSMINDB_URI` wins over `DATABASE_URL` (source: `app/.server/env.ts`, `drizzle.config.ts`, `app/.server/AGENTS.md`).
- **Can a terminal reach the Aspire database?** No, Aspire generates the password (source: comment on `cms-seed` in `aspire-apphost/apphost.mts`). This is why Q4 proposes Aspire resources.
- **Is a `blog_posts` table needed?** No, blog content lives in Strapi (source: #20, issue #3 Context).
- **Where do the shared enum types go?** `app/lib/`, which is isomorphic with no server imports (source: `AGENTS.md` → "Architecture rules").
- **Is the `migrations/` folder linted?** No, it's already excluded in `biome.json`.
- **Does the Aspire SDK support run-to-completion dependencies?** Yes. `waitForCompletion`, `withExplicitStart`, `withRunScript` and `withParentRelationship` exist on JavaScript app resources (source: generated `aspire-apphost/.aspire/modules/aspire.mts`).
- **How should DB integration tests behave?** Use `describe.skipIf(!hasDatabase)`, dynamic imports, and close the pool in `afterAll` (source: `app/.server/AGENTS.md` → "Tests", `app/.server/db/queries/health.test.ts`).

## Steps
- [x] **1. Shared enums in `app/lib/enums.ts`.** `export const GENDERS = ["women", "men", "unisex"] as const; export type Gender = (typeof GENDERS)[number];`, and the same for `ORDER_STATUSES` (`pending`, `paid`, `shipped`, `completed`, `cancelled`, `returned`, `unclaimed`), `PAYMENT_STATUSES` (`unpaid`, `paid`, `refunded`) and `CART_STATUSES` (`active`, `converted`, `abandoned`), following the `SOCIAL_PLATFORMS` style in `app/lib/cms.ts`. Add `enums.test.ts` asserting the exact arrays. Check: `pnpm typecheck`, `pnpm test`.
- [x] **2. Drizzle schema in `app/.server/db/schema.ts`.** `genderType = pgEnum("gender_type", GENDERS)` and the other three enums (all exported so drizzle-kit creates them).
  - `users`: `id: serial().primaryKey()`, `fullName: varchar({ length: 255 }).notNull()`, `email: varchar({ length: 255 }).notNull().unique()`, `passwordHash: varchar({ length: 255 }).notNull()`, `phone: varchar({ length: 50 })`, `acquisitionChannel: text().notNull().default("direct")`, `lastLoginAt: timestamp({ withTimezone: true })`, `createdAt: timestamp({ withTimezone: true }).notNull().defaultNow()`.
  - `products`: `id` serial PK, `publicId: uuid().notNull().unique().default(sql\`uuidv7()\`)`, `title`/`brand` varchar(255) not null, `gender: genderType().notNull()`, `fragranceFamily: text()`, `description: text()`, `price: numeric({ precision: 10, scale: 2 }).notNull()`, `volumeMl: integer().notNull()` (one unit), `packSize: integer().notNull().default(1)`, `stockQuantity: integer().notNull().default(0)`, `imageUrl: text()`, `createdAt` as in `users`. Third argument: `check("products_stock_quantity_check", sql\`${t.stockQuantity} >= 0\`)`, `check("products_pack_size_check", sql\`${t.packSize} > 0\`)` and `index("products_gender_idx").on(t.gender)`.
  - Add a comment that `last_login_at`, `acquisition_channel` and `fragrance_family` are ML features that must never be dropped.
  - `schema.test.ts`: `genderType.enumValues` equals `GENDERS` (and the same for the others). Use `getTableConfig(products)` / `getTableConfig(users)` to assert column types, notNull, defaults, the check and the index. Check: `pnpm typecheck`, `pnpm test`.
- [x] **3. Generate the first migration.** Add scripts: `"db:generate": "drizzle-kit generate"`, `"db:migrate": "drizzle-kit migrate"`. Run `pnpm db:generate --name core_schema`. Review the SQL: `CREATE TYPE` for all 4 enums, both tables, `numeric(10, 2)`, `timestamp with time zone DEFAULT now()`, `uuid DEFAULT uuidv7()`, the unique email and `public_id`, both checks and the index. Commit the SQL together with `meta/`.
- [x] **4. Rollback support.** Write `app/.server/db/rollbacks/0000_core_schema.sql`: `DROP TABLE "products"; DROP TABLE "users"; DROP TYPE "cart_status_type"; DROP TYPE "payment_status_type"; DROP TYPE "order_status_type"; DROP TYPE "gender_type";` (reverse order, split with drizzle's `--> statement-breakpoint` style, or execute as one statement).
  - In `migrator.ts`, `migrateLatest(db)` calls `migrate(db, { migrationsFolder })` from `drizzle-orm/node-postgres/migrator`. `rollbackLatest(db)` reads `migrations/meta/_journal.json` (validated with zod), selects the latest row from `drizzle.__drizzle_migrations`, maps `created_at` to the journal `tag`, then inside `db.transaction` runs `rollbacks/<tag>.sql` and deletes the row. It returns the rolled-back tag, or `null` when nothing is applied.
  - `scripts/rollback.ts`: build a db with `createDb(getDatabaseUrl(process.env))` after loading `.env`, call `rollbackLatest`, log the result and `end()` the pool. Add the `"db:rollback": "tsx app/.server/db/scripts/rollback.ts"` script and the `tsx` devDependency (`pnpm add -D tsx`).
  - Refactor `index.ts` to `createDb(connectionString)` and `env.ts` to `getDatabaseUrl(source)` (with tests in `env.test.ts`).
- [x] **5. Migration integration test (`migrator.test.ts`).** Skipped when there's no DB. Using the configured server, create a throwaway database `jassmin_migrate_test_<random>` and connect a pool to it. Then:
  1. `migrateLatest`: the `information_schema` / `pg_type` queries show both tables, the 4 enums with the right labels, the `products_gender_idx` index and the `products_stock_quantity_check` / `products_pack_size_check` constraints.
  2. Inserting a product with `stockQuantity: -1` or `packSize: 0` is rejected, and so is a `NULL` in any NOT NULL column.
  3. A duplicate `users.email` or `products.public_id` is rejected.
  4. The defaults are applied (`stock_quantity = 0`, `pack_size = 1`, `acquisition_channel = 'direct'`, `created_at` set, `public_id` is a version-7 UUID, i.e. its 13th hex digit is `7`).
  5. `rollbackLatest`: no tables or types remain, and `__drizzle_migrations` is empty.
  6. `migrateLatest` again succeeds.

  In `afterAll`, close the pools and drop the database. This covers "up and down cleanly on an empty database".
- [x] **6. Seed.** `seed-data.ts`: `export const SAMPLE_PRODUCTS: (typeof products.$inferInsert & { publicId: string })[]` with about 9 perfumes: 3 women, 3 men, 2 unisex, plus "Набір тестерів 3 × 10 мл" (unisex, `packSize: 3`, `volumeMl: 10`), with realistic UAH prices as strings (e.g. `"2450.00"`), stock and fragrance families. Each product has a fixed UUID v7 `publicId` written into the file (generated once, e.g. with `select uuidv7()`).
  - `seed.ts`: `seedProducts(db)` runs `db.insert(products).values(SAMPLE_PRODUCTS).onConflictDoNothing({ target: products.publicId }).returning({ id: products.id })` in `db.transaction` and returns `{ inserted }`.
  - `scripts/seed.ts` is the CLI, wired to `"db:seed": "tsx app/.server/db/scripts/seed.ts"`.
  - `seed.test.ts` unit checks: every gender is present, a tester set with `packSize: 3` exists, prices match `/^\d+\.\d{2}$/`, stock is ≥ 0, `packSize` is ≥ 1, and every `publicId` is a unique UUID v7.
  - `seed.test.ts` integration check, on the throwaway-DB helper from step 5 (extract it into a small test util): the first run inserts every sample product, and a second run inserts 0 with the row count unchanged.
